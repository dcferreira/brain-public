● The review turned up two real issues, and a Sonnet subagent is fixing those plus three smaller ones now:

  1. Probes could freeze the app. The shelled-out tools had no timeout, and the probes run while the app holds its main state
     lock. If GNOME Shell or PipeWire hung, complete, skip and snooze would block until it recovered. The fix is a 2 s
     deadline on every tool call. If a call runs over, the tool is killed and the probe treats that as "not quiet".
  2. The mic could look in use forever. The current check counts any recording mic source, so an always-on reader would pause
     nudges indefinitely. That includes EasyEffects input processing, filter chains and level meters. The fix is to count
     only actual recording streams from apps, skipping paused streams, desktop-audio recording, pavucontrol level meters and
     EasyEffects' own stream. It'll be tested against real pactl output captured on your machine.
  3. Smaller fixes:
     - Make the tool runner swappable, so the idle fallback and "tool missing" cases can be unit-tested.
     - Fail loudly when pactl returns JSON that isn't a list.
     - Run the tools with LC_ALL=C so their output format doesn't depend on locale.

  Left out on purpose, for the PR notes:
  - Lock scope: the reviewer also suggested releasing the lock around the probe in list_due_now. That code is in
    commands/handlers.rs, outside this worker's probe-only scope.
  - Idle-only probe: the scheduler runs every probe just to read idle. That's in runtime.rs, which the cooldown worker owns.
  - No log on degrade: a probe that falls back to "not quiet" doesn't log anything yet.
  - Older pactl: PulseAudio before 16 has no JSON output, so mic pause can't work on Debian 11 / RHEL 9-era systems.
  - KDE idle unverified: I haven't been able to check whether the screensaver fallback actually works on KDE.
